- **An incident:** `list_allowed_directories`, `edit_file` and `get_file_info` all returned: `invalid outputSchema: JSON Schema declares an unsupported dialect ("$schema": "http://json-schema.org/draft-07/schema#")`. The error comes from the client side before the call reaches the machine, so retrying does not help.
- **A note:** in a cloud session linked to the machine the tools arrived under one connector prefix and worked normally, while under another prefix the same tools failed with the same error. The trap follows the tool path, not the whole cloud session: try `list_allowed_directories` once first before assuming a failure.
- **A second note:** within the same cloud session the prefix can change mid-session — `edit_file` worked under the first prefix, then the tools moved to the second prefix and `edit_file` failed with the same outputSchema error. The trap follows the prefix, and the prefix can change inside a session. The alternative that worked: TR-0026 (build in the sandbox, write whole with `create_vault_file`, and match the sha).
