- **Part 1 — an initial explanation (later shown not to be general):** after correcting a link of the form `[[Architecture-Decision-Records#ADR-010|ADR-010]]` with `search_and_replace` (an immediate `search_vault_simple` check succeeded), `audit --check links` returned the same old error. At that time `SNAPSHOT`/`head` in the `audit` output stayed on an old commit across two consecutive runs, while `git status` showed the file `modified` — so the obvious explanation seemed to be that the periodic external backup had not yet picked up the edit.
- **Part 2 — the same day, after the periodic backup picked up a new commit (`git status` clean for the file), the error stayed exactly as it was.** A careful check proved that `head` in the `audit` output **matches exactly** the real `git rev-parse HEAD` — so the first explanation (a stale snapshot) is **not enough here**; the live file and the commit are identical.
- **The deep investigation:** reading `AI-Agent/scripts/audit.py` and `_vaultlib.py` directly showed that `iter_md()`/`read()` read from disk directly (`os.walk`, `Path.read_text`), not from git, and that the R12 logic (`frag.split("#")[-1].strip() not in heads`) is correct in itself. Rebuilding the same `Ctx`/`resolve`/R12 loop by hand — with the same imports, the same file, at the same moment — gave `check in heads == True` (**no error**), while the real `run_script audit` call at the same moment kept returning `R12-missing` for the same link.
- **The conclusion:** the difference between a manual run of the source logic (passed) and a real `run_script audit` run (failed), despite every visible input matching (the file, HEAD, the code), was not settled — it may be the execution environment of `run_script` itself (a different temporary copy of the file, a cache, or a read path different from the live disk), not the source code that was read.
- **The practical rule:** an `R12-missing` error from `run_script audit` — or any audit error about a link or text that was verified with a live tool in the same session — is not accepted at once as evidence of failure, even when `head` matches `git rev-parse HEAD`. Re-verify by an independent method (`get_vault_file_partial` with `mode: heading` on the same literal heading, or a manual simulation of the check logic through a sandbox exec) before accepting an audit result or before any further edit built on it.
