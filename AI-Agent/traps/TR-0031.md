id: TR-0031
title: Adding or removing a vault artifact without updating its consumer map silently passes
kind: process
rule: Any addition or removal of a vault artifact (a skill, a script, a progress line) must update its declared count in AI-Agent/schema/consumer-map.yaml in the same commit. The commit gate (audit.py --ratchet) enforces a consumer_drift check that blocks the commit when the map's counters (skills, tools, progress) disagree with reality on disk. Counters in consumer tests must read their expected values from the map, never hard-code them.
status: active
since: 2026-10-23
related:
- '[[TR-0029]]'
created: 2026-10-24
symptoms: A consumer test or a live audit fails with an absolute count mismatch (e.g. skills 22 -> 23, tools 53 -> 54) after a new artifact is committed. The addition passes the standard schema and frontmatter gates silently because no structural check ties the artifact to its declared counter.
cause: The commit gate audited the vault files structurally (26 checks) but did not track artifact-to-consumer relationships (D5). Absolute counters were hard-coded inside consumer test files (D1), so adding an artifact broke the consumer rather than the gate, leaving the failure invisible until a manual, unrelated audit (D6 - false confidence in gate coverage).
workaround: None needed; structurally fixed via the consumer_drift gate.
fix_status: fixed
regression_check: 'negative test: create a dummy skill folder under AI-Agent/skills/ and run audit.py --ratchet; the commit must block with error CDRIFT-drift (map skills=N reality=N+1). Delete the folder and re-run; it must pass with GATE CLEAR blocking=0.'
---
- **The incident:** a skill was added (a commit); it was sound schema-wise, but the consumer counter in a consumer test broke (a count off by one) and was found only by a late manual check — the gate did not object because it does not see the relation between `skills/` and the consumer.
- **The root treatment:** the file `AI-Agent/schema/consumer-map.yaml` became the single source of truth for the live counters (skills, tools, progress), and the `consumer_drift` check in `audit.py` matches the map with reality on disk (counting folders/scripts/progress lines). Any difference = a blocking error (CDRIFT-drift) that stops the commit until the map is updated in the same commit.
- **The anchoring:** the anchor `gate_baseline.json` protects the check from self-blindness, and the negative test passed (a dummy skill → blocking at once) while the positive test is clean (0 drift).
- **The structural lesson:** every absolute counter inside test code is a possible drift point; scores are read from the map (`consumer-map.yaml`), not from code. The `consumer_drift` check runs once per audit (not per file) to avoid the cost of repeated counting.
