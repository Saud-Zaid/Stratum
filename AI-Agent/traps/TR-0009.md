- **An environmental trap (not a tool) — the "Update time on edit" plugin:** an installed Obsidian plugin can update a frontmatter field `updated` (from `mtime`) on every file save, and write `created` (from `ctime`) when it is missing — **whatever the source of the save** (the agent, the owner by hand, or anything else). In templates (`Templates/*.md`) this is dangerous: any save (even a simple manual review) replaces the dynamic Templater code `<% tp.date.now(...) %>` in `created` with a fixed literal date. **The right fix (outside the agent's ability):** the plugin supports "Ignore folder for all update" — the owner needs to exclude the whole `Templates/` folder in its settings. **Until that is done:** after opening any template for editing, check at once that `created` is still Templater code, not a literal date — do not assume it is intact just because I did not touch it myself.

**Current state:** `updated` is retired — the plugin was stopped and the field no longer exists in any note, so the rule above is the current guard. `updated` is not a registered key, so `audit.py` reports it as `FM-unknown` and the pre-commit hook blocks it.
