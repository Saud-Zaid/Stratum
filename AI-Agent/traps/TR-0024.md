---
id: TR-0024
title: Standalone block id right after a table is unpatchable, even with a blank line
kind: tool
tools:
- patch_vault_file
rule: For a table's block id, attach it to the end of a real paragraph line after the table (never leave it as a bare ^id line), even with a blank line separating it from the table — a bare id line is treated as still inside the table and patch_vault_file refuses to touch it.
status: active
since: 2026-09-13

created: 2026-09-14
---
- **An incident (a test of block-id handling):** targeting a standalone block id on its own line (`^t-20260913-03`) directly after a Markdown table — even **with a blank line separating it from the table** (the form recommended by the official Obsidian documentation itself for table ids) — was refused by `patch_vault_file` with an explicit message: `"resolved to line N but it is inside a markdown table or fenced code block"`. The same refusal repeated even with an extra paragraph after the id.
- **The decisive test:** when the same id was attached to the end of **an actual text paragraph line** instead of being a standalone line (`paragraph text... ^t-20260913-04`), `patch_vault_file(block, replace)` succeeded at once with no problem.
- **The likely cause:** the tool classifies any "bare" id (no earlier text on the same line) that sits directly after a table as part of the table's own range, whatever the surrounding blanks — it makes no clear difference between "the last row of the table" and "a standalone line with no content that follows the table".
- **The effect on the decision:** the form "tables: the id on a standalone line with a blank line before and after it" is **not enough in practice for this tool**, although it is the recommended practice in the general Obsidian documentation.
- **The practical rule:** for a block id that belongs to a table, never leave it on a standalone line — attach it to the end of an actual text line (a short explanatory sentence about the table, or the first line of the next paragraph) even if this text is formally unnecessary.
