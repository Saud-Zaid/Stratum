---
id: TR-0029
title: An empty gate commit anchors HEAD, not the working tree
kind: process
rule: Before asking the vault owner for a gate commit that stamps what is staged, check `git status` for the files it must carry. If the approved edits are already committed (the auto backup ran), an empty commit works. If they are still uncommitted, ask for `git add -A` then the gate commit. After the commit, check that the stamped snapshot includes the newest decision before reporting the gate closed.
status: active
since: 2026-10-13
superseded_by: ''
created: 2026-10-13
---
- **The incident:** a hook stamps the elements "as staged". An empty commit was requested after a decision was written, and the automatic backup had not yet committed it. The stamp came out without the newest decision, i.e. it stamped the previous version a second time. A later verify step did not catch it because it compares the tree with the snapshot, and the newest decision explains the difference.
- **The right way:** `git add -A` and then the gate commit: the stamp then includes the newest decision.
- **The opposite on another system:** the backup came first, so the first commit found nothing and was left empty. Both have the same cause: what gets stamped is what is in the index, not what is in the files.
