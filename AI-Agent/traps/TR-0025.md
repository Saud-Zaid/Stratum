---
id: TR-0025
title: create_vault_file decodes \u escapes in written content
kind: tool
tools:
- create_vault_file
rule: A four-digit backslash-u escape in content written by create_vault_file lands as the literal character (a doubled backslash lands as two backslashes, so there is no way to write it). In code, spell code points as eight-digit backslash-U escapes or chr(); after any .py rewrite, check git diff for lines changed by accident.
status: active
since: 2026-10-01
superseded_by: ''
related:
- '[[TR-0022]]'
created: 2026-10-01
---
- **An incident:** rewriting `audit.py` completely with `create_vault_file` turned the four-digit backslash-u escapes (064B, 0621 and 2014) into their actual characters (an invisible diacritic inside a regex). The behaviour did not change, but the source became unreadable.
- **The test:** `\\u064B` is written with two backslashes, so there is no way to write the four-digit form literally. The other escapes (`\n`, `\s`, `\"` and `\U0001F4C5`) are intact.
- **The fix:** the eight-digit form `\U0000064B` is written as it is and gives the same meaning in Python and in a regex.
- **Verification:** after any rewrite of a `.py` file, `git diff -U0` run through `exec_python` shows any line that changed by accident.
